# Pause: auto-pause and manual pause (plan.md task 1.6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (PS chose inline). **PS commits manually: never run `git commit`; say "ready to commit" with a suggested message at the end of each part.**

**Goal:** Time and distance stop counting while the drive is paused, either automatically (stopped for 5 min) or by the Pause button, and resume cleanly without adding a straight line across the gap.

**Architecture:** Pause lives in the pure live stats engine (`src/lib/live-stats.ts`). Auto-pause is derived from the points themselves (so it replays identically after an app restart). Manual pause/resume are timestamped events stored in SQLite and merged with points by time. While manually paused the background task does not store points at all.

**Tech Stack:** Expo SDK 58, expo-sqlite, node:test.

## Global Constraints

- Distance accuracy is the Phase 1 gate: existing characterization tests (`tests/live-stats.test.mts`) must pass **unchanged**.
- Auto-pause: stopped = under 3 km/h (`CLEANING.stoppedBelowKmh`) for `AUTO_PAUSE_MS` = 5 min. Idle time before the trigger is not counted.
- No points are stored during a manual pause. Controls (Pause/Resume) lock above 10 km/h like Hold to finish.
- Colours from `src/theme` only. No new native library. Do not edit `android/` or `ios/`.
- Done = typecheck, eslint, `npm test` clean; update `handoff.md`, tick 1.6 in `plan.md`.

## Review Focus

1. Pause then resume somewhere else (manual pause at a stop, then drive off): no straight-line distance across the gap, time excludes the pause.
2. App killed while paused, reopened: HUD shows the same paused state and the same Time (events replay from SQLite).
3. A 5-minute red light or traffic jam in the middle of a drive: auto-pauses, resumes on the first moving point, Time excludes the idle 5 min, distance has no jump.
4. Pause pressed twice quickly, Resume while auto-paused, Finish while paused: no crash, no double events, the drive still ends and saves.
5. Points that arrive late (batched by Android) with a timestamp before the pause started are still kept.

### Task 1 (1.6a): Pause in the engine, test first

**Files:** `src/lib/live-stats.ts`, `tests/pause.test.mts`, `package.json`.

**Interfaces (produces):**
- `export const AUTO_PAUSE_MS = 300_000;`
- `createLiveStats(options?: { autoPauseMs?: number }): LiveStats`; `Infinity` disables auto-pause.
- `LiveStats` gains: `pause(ts: number): void` (manual; points arriving while manually paused are counted as raw but otherwise ignored), `resume(ts: number): void` (manual; also valid while auto-paused; the next accepted point becomes the new baseline, no distance across the gap), `pauseState(): { kind: 'manual' | 'auto'; since: number } | null`, `elapsedAt(nowMs: number): number` (seconds; frozen while paused, extrapolated to `nowMs` from the last accepted point otherwise).
- `DriveSummary.elapsedS` now means active time (excludes paused time); equal to the old value when nothing was paused.
- `summarize(points, pauses?: { ts: number; type: 'pause' | 'resume' }[])`: merges events with points by time (event first on equal ts).

### Task 2 (1.6b): Persistence and recorder

**Files:** `src/features/recording/db.ts`, `location-task.ts`, `recorder.ts`.

**Interfaces (produces):**
- Table `pause_events (id INTEGER PRIMARY KEY AUTOINCREMENT, session_id INTEGER NOT NULL, ts INTEGER NOT NULL, type TEXT NOT NULL)`.
- `insertPauseEvent(sessionId: number, ts: number, type: 'pause' | 'resume'): void`, `getPauseEventsSince(sessionId: number, afterId: number): { id: number; ts: number; type: 'pause' | 'resume' }[]`.
- kv key `manual_pause_since` (ms, or absent); `getManualPauseSince(): number | null`.
- `pauseRecording(): void` and `resumeRecording(): void` in `recorder.ts`: write the event and the kv key with `Date.now()`; idempotent (pause while paused, resume while running do nothing).
- `location-task.ts`: when `manual_pause_since` is set, drop points with `ts >= since` before `insertPoints`. Points with `ts < since` are kept (late batches).
- `endActiveSession` / `stopRecording` also clear `manual_pause_since`.
